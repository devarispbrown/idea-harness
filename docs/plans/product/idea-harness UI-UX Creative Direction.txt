idea-harness
UI / UX Creative Direction
Version: 1.1
Direction: Calm Command Center
Product principle: Calm on the surface. Rigorous underneath.




1. Design Thesis
idea-harness should not look or behave like:


     • Jira with AI
     • Trello with agents
     • a chat app
     • an IDE full of autonomous-agent terminals
     • a generic observability dashboard

The user is not managing agents.


The user is developing an idea.


The interface should answer five questions quickly:



  What are we building?

  What have we learned?


  What changed?

  What still needs judgment?

  What happens next?


Everything else is progressively disclosed.




2. Emotional Goal
Using idea-harness should feel like supervising a very strong product and engineering organization that
works independently but keeps the user in control.

4. Visual Language
Use:


       • neutral surfaces
       • restrained borders
       • high-quality typography
       • subtle depth
       • limited accent color
       • strong spacing hierarchy
       • compact metadata
       • large readable product prose

State color is functional.


Suggested semantic use:



  Active             blue/accent
  Passed             green
  Attention          amber
  Blocked            red
  Neutral            grayscale


Do not use color as the only state indicator.

9. Current Understanding
This should be a signature component.


It is the continuously updated representation of:


      • what is being built
      • target user
      • value
      • major constraints
      • key decisions
      • unresolved questions

Users returning after hours or days should orient themselves here.

10. Recommended Next Move
Visible when a consequential next action exists.


Example:



  RECOMMENDED NEXT MOVE

  Resolve how conflicting decisions are handled.

  Why
  Storage, UX, and verification depend on it.

  [Review decision]


This translates workflow complexity into product language.




11. Decisions
The global Decisions view is for human judgment.


Categories:



  Need Your Decision
  Blocked
  Recommended Changes
  For Awareness


Do not call every item an approval.


A product decision and permission request are different concepts.

13. Agent Conversations
Direct conversations with individual experts may exist as an advanced capability.


They should not be the default coordination model.


The user should not have to manually arbitrate:



  PM chat
  Architect chat
  Designer chat
  Security chat


idea-harness should synthesize those perspectives first.

39. Accessibility
The idea-harness UI itself must support:


      • keyboard navigation
      • visible focus
      • semantic labels
      • screen readers
      • contrast
      • non-color state communication

      • responsive layouts
      • reduced motion preferences

  judgment
  discipline
  precision
  momentum
  clarity

  magic
  autonomy theater
  futurism
  playfulness

                                                     22
43. Design Principle Checklist
Every new feature should ask:


Is this something the user needs to know now?

If not, hide it one level deeper.


Is this a product decision or system metadata?

Product decision gets visual priority.


Can idea-harness synthesize this instead of making the user coordinate agents?

If yes, synthesize it.


Does this communicate uncertainty honestly?

Avoid fake precision.


Does this expose evidence?

Important claims and reviews should be traceable.


Can the user recover?

Failures should show next actions.




44. Signature Interactions
The product should become recognizable through:



  Current Understanding
  Recommended Next Move
  Decisions
  What Changed
  Why
  Semantic Diff
  Adversarial Review


These are more important to the identity than the Kanban itself.




                                                    23
45. Final UX Philosophy
The interface should embody:


       Show me the idea, what we've learned, what changed, what remains uncertain, what
       needs my judgment, and what happens next. Hide the machinery until I ask for it.


The user should never feel like the project manager for a collection of AI agents.


They should feel like the product leader of an unusually capable team.
