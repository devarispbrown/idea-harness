6. Core Architectural Invariants
      1. Git is optional.
      2. Workers cannot directly mutate the canonical workspace.
      3. Every source mutation is a ChangeSet.
      4. Every ChangeSet receives independent review.
      5. Every material plan receives independent review.
      6. Authors cannot self-review.
      7. The deterministic engine controls authorization.
    8. Models cannot grant capabilities.
    9. Skills are non-executable.
   10. Tools and Executors explicitly declare capabilities.
   11. Security is enforced outside prompts.
   12. Large content does not live inline in SQLite.
   13. Relational state is authoritative.
   14. Events accompany every meaningful durable state transition.
   15. Events and relational state update atomically.
   16. Every Run produces immutable provenance.
   17. Project ID scopes every security-sensitive operation.
   18. User edits are never silently overwritten.
   19. Canonical workspace writes are serialized.
   20. Infrastructure and semantic failures have distinct recovery.
   21. Reviews may vary in depth but cannot disappear.
   22. Draft agent output is lower-trust than approved output.
   23. Human-required approvals cannot be satisfied by agents.
   24. Security failures fail closed.

39. ApplyJournal
Filesystem + SQLite cannot be committed atomically.


Therefore canonical ChangeSet application requires a durable journal.



  prepared
  workspace_mutated
  committed
  rolled_back
  recovery_required




                                                      21
Apply sequence:


     1. lock canonical workspace
     2. verify base
     3. create rollback snapshot
     4. persist prepared
     5. apply patch
     6. verify hashes
     7. persist workspace_mutated
     8. transactionally mark ChangeSet applied + event + journal committed
     9. release lock
    10. garbage-collect rollback later

Startup reconciliation handles incomplete journals.
